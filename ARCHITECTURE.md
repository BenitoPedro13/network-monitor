# Network Monitor — Architecture Document

**Author:** Benito Pedro  
**Date:** 2026-06-09  
**Status:** In Progress — Phase 1 Scoped  
**Scope:** Personal device monitoring (per-device DNS, not router-wide)

---

## 1. Problem Statement

Monitor all DNS traffic generated by personal devices (MacBook, iPhone, etc.) in a home network to detect suspicious activity — unknown domains, unusual query frequency, or known-threat destinations — and visualize it on a real-time dashboard.

DNS was chosen as the capture layer because:
- Every network connection begins with a DNS resolution
- DNS gives domain-level visibility (~95% coverage) without requiring deep packet inspection
- AdGuard Home provides DNS logging with source IP attribution out of the box
- No router firmware modification required for personal-device-only scope

## 4. Database Schema

The `Device`, `DnsEvent`, and `Alert` tables are already migrated. `IpGeoCache` and `SystemState` require a new migration (Phase 1).

### 4.1 Device

Registered personal devices. Only devices with a matching `ipAddress` row will have their DNS events stored. Unknown IPs are silently ignored by the collector.

```prisma
model Device {
  id         String     @id @default(cuid())
  name       String                          // e.g. "macbook-pro", "iphone-benito"
  ipAddress  String     @unique              // must match DHCP lease — keep static
  macAddress String?    @unique
  owner      String?
  deviceType String?                         // "laptop", "phone", "tablet"
  createdAt  DateTime   @default(now())
  updatedAt  DateTime   @updatedAt
  dnsEvents  DnsEvent[]
  alerts     Alert[]
}
```

**Important:** `ipAddress` is the join key between AdGuard logs and the Device table. Devices must have a static local IP (via router DHCP reservation or OS-level static IP) or the mapping breaks silently.

### 4.2 DnsEvent

One row per DNS query captured from AdGuard Home.

```prisma
model DnsEvent {
  id          String   @id @default(cuid())
  queriedHost String                         // e.g. "api.github.com"
  queryType   String   @default("A")         // A, AAAA, CNAME, MX, etc.
  sourceIp    String                         // device IP at query time
  responseIp  String?                        // resolved IP (null if blocked/NXDOMAIN)
  blocked     Boolean  @default(false)
  queriedAt   DateTime                       // timestamp from AdGuard log
  createdAt   DateTime @default(now())
  deviceId    String

  @@index([deviceId, queriedAt])             // timeline queries per device
  @@index([queriedHost, queriedAt])          // domain frequency analysis
}
```

Geo data is not stored on `DnsEvent` directly. Grafana queries join `DnsEvent.responseIp` with `IpGeoCache.ip` at query time. This avoids storing geo columns on millions of event rows — the cache table has at most one row per unique destination IP.

### 4.3 IpGeoCache

Lookup cache for IP geolocation. Populated by the collector on first encounter of each unique `responseIp`. Refreshed if `resolvedAt` is older than 30 days (IPs can change ownership).

```prisma
model IpGeoCache {
  ip          String   @id                   // e.g. "140.82.112.5"
  country     String?                        // e.g. "United States"
  countryCode String?                        // ISO 3166-1 alpha-2, e.g. "US"
  city        String?                        // e.g. "Seattle"
  lat         Float?                         // latitude  — used by Grafana Geomap
  lon         Float?                         // longitude — used by Grafana Geomap
  asn         String?                        // e.g. "AS13335"
  isp         String?                        // e.g. "Cloudflare, Inc."
  resolvedAt  DateTime @default(now())       // when this entry was last resolved
}
```

**Grafana join pattern:**
```sql
SELECT e."queriedHost", g."country", g."city", g."isp", g.lat, g.lon, count(*) as queries
FROM "DnsEvent" e
LEFT JOIN "IpGeoCache" g ON e."responseIp" = g.ip
WHERE e."deviceId" = $device_id
GROUP BY e."queriedHost", g."country", g."city", g."isp", g.lat, g.lon
```

### 4.4 Alert

Generated by the collector's anomaly detection rules. Not sourced from AdGuard directly.

```prisma
model Alert {
  id          String      @id @default(cuid())
  type        AlertType                      // UNKNOWN_DOMAIN | HIGH_FREQUENCY | THREAT_MATCH
  status      AlertStatus @default(OPEN)     // OPEN | ACKNOWLEDGED | RESOLVED
  title       String
  description String?
  riskScore   Int         @default(0)        // 0–100
  createdAt   DateTime    @default(now())
  updatedAt   DateTime    @updatedAt
  deviceId    String

  @@index([deviceId, status])
}
```

**Risk score scale:**
- `0–30` — informational
- `31–60` — low concern, worth watching
- `61–80` — elevated, review soon
- `81–100` — high priority, act now

## 5. AdGuard Home API Contract

The collector depends on this endpoint. AdGuard Home must be running and the initial web wizard must be completed before the collector starts.

```
GET http://localhost:3000/control/querylog
    ?limit=1000
    &older_than=<RFC3339 timestamp>   ← pagination cursor
    &response_status=all

Authorization: Basic <base64(user:password)>
Content-Type: application/json
```

**Response shape (relevant fields):**

```json
{
  "data": [
    {
      "time": "2026-06-09T14:32:01.123Z",
      "question": {
        "name": "api.github.com",
        "type": "A"
      },
      "client": "192.168.1.10",
      "status": "NOERROR",
      "reason": "NotFilteredNotFound",
      "rules": [],
      "answer": [
        { "type": "A", "value": "140.82.112.5" }
      ]
    }
  ],
  "oldest": "2026-06-09T13:00:00.000Z"
}
```

**Mapping to DnsEvent:**

| AdGuard field | DnsEvent field |
|---|---|
| `time` | `queriedAt` |
| `question.name` | `queriedHost` |
| `question.type` | `queryType` |
| `client` | `sourceIp` |
| `answer[0].value` | `responseIp` |
| `reason.startsWith("Filtered")` | `blocked = true` |

## 6. Collector Service Design

**Location:** `apps/api/src/collector.ts` (entry point), extracted into modules.

### 6.1 Module Structure

```
apps/api/src/
├── index.ts              ← starts the collector loop
├── collector/
│   ├── poll.ts           ← fetches AdGuard API, returns raw events
│   ├── mapper.ts         ← maps raw AdGuard event → DnsEvent shape
│   ├── writer.ts         ← upserts DnsEvent + IpGeoCache rows via Prisma
│   ├── cursor.ts         ← manages last-seen timestamp (in-memory + DB)
│   ├── geo/
│   │   ├── index.ts      ← exports enrichIp(ip) → GeoResult
│   │   ├── lookup.ts     ← reads GeoLite2-City.mmdb + GeoLite2-ASN.mmdb via maxmind npm pkg
│   │   └── cache.ts      ← checks IpGeoCache before calling lookup, writes new entries
│   └── anomaly/
│       ├── index.ts      ← orchestrates rules after each batch
│       ├── unknownDomain.ts
│       ├── highFrequency.ts
│       └── threatMatch.ts
```

### 6.2 Polling Loop

```
┌─ start ────────────────────────────────────────────────────────┐
│  1. load cursor (last processed timestamp)                     │
│  2. GET /control/querylog?older_than=cursor                    │
│  3. filter: keep only known device IPs                         │
│  4. map AdGuard events → DnsEvent shapes                       │
│  5. for each unique responseIp in batch:                       │
│       a. check IpGeoCache — if hit and age < 30d → use cache  │
│       b. if miss → read GeoLite2 .mmdb files (offline, fast)  │
│       c. upsert IpGeoCache row                                 │
│  6. deduplicate DnsEvent rows against existing rows            │
│  7. bulk insert DnsEvent rows                                  │
│  8. run anomaly rules on new batch                             │
│  9. insert Alert rows for triggered rules                      │
│  10. advance cursor to newest event timestamp                  │
│  11. wait 30s                                                  │
│  12. repeat                                                    │
└────────────────────────────────────────────────────────────────┘
```

**Cursor strategy:** The cursor is the `queriedAt` timestamp of the most recently processed event. It is kept in memory and flushed to a `collector_state` key in a small `SystemState` table (to be added via migration) so the cursor survives restarts. On first run the cursor defaults to `now() - 24h` to backfill one day.

### 6.3 Anomaly Detection Rules

Rules run synchronously after each batch. Each rule receives the batch of newly inserted `DnsEvent` rows plus a reference to Prisma for historical queries.

**Rule: `UNKNOWN_DOMAIN`**
- Trigger: a domain queried that has never been seen before from that device within the last 30 days
- Risk score: 30 (informational — a new domain isn't inherently suspicious)
- Dedup: only create one alert per `(deviceId, queriedHost)` pair per 24h window

**Rule: `HIGH_FREQUENCY`**
- Trigger: more than 100 queries to the same domain from the same device within any 5-minute window
- Risk score: 65 (unusual — may indicate beaconing/malware C2)
- Dedup: one alert per `(deviceId, queriedHost)` per hour

**Rule: `THREAT_MATCH`**
- Trigger: queried domain appears in AdGuard Home's blocked list (i.e., `blocked = true` in the event)
- Risk score: 80
- Dedup: one alert per `(deviceId, queriedHost)` per 24h

### 6.4 Geo Enrichment Detail

**Library:** `maxmind` npm package — reads `.mmdb` binary files directly in-process. No HTTP calls, no rate limits, sub-millisecond lookup.

**Files required (downloaded once, updated weekly):**
- `GeoLite2-City.mmdb` — country, city, lat/lon
- `GeoLite2-ASN.mmdb` — autonomous system number + organization name

**How to obtain:**
1. Register free account at maxmind.com
2. Generate a license key (free tier)
3. Download both `.mmdb` files via the MaxMind download API or `geoipupdate` CLI
4. Place in `./geoip/` directory (gitignored — binary files, updated separately)

**GeoLite2 accuracy:**
- Country: ~99% accurate
- City: ~83% accurate for most countries (good enough for anomaly detection)
- ASN: ~99% accurate — tells you "Amazon AWS", "Cloudflare", "Hetzner Online GmbH", "Unknown ISP in Moldova"

**What the enrichment tells you:**
- A `responseIp` in `RU`, `CN`, `KP` or a high-risk ASN is a strong compromise signal
- Seeing your iPhone talk to `AS209242` (a known bulletproof hosting provider) is far more actionable than just seeing an IP
- Legitimate traffic clusters in a handful of countries (US, EU, CDN providers) — outliers stand out visually on the map

**Cache strategy:**
- IP ownership changes are rare — 30-day TTL is safe
- On collector restart the cache is already warm in Postgres — no cold-start re-resolution needed
- Private/RFC1918 IPs (`10.x`, `192.168.x`, `172.16-31.x`) are skipped — MaxMind has no data for them and they are internal addresses

## 7. Grafana Setup

### 7.1 Addition to docker-compose.yml

```yaml
grafana:
  image: grafana/grafana:11-oss
  container_name: network_monitor_grafana
  restart: unless-stopped
  ports:
    - "${GRAFANA_PORT:-3001}:3000"
  environment:
    GF_SECURITY_ADMIN_USER: ${GRAFANA_USER:-admin}
    GF_SECURITY_ADMIN_PASSWORD: ${GRAFANA_PASSWORD:-network_monitor}
    GF_USERS_ALLOW_SIGN_UP: "false"
  volumes:
    - grafana_data:/var/lib/grafana
    - ./grafana/provisioning:/etc/grafana/provisioning
  depends_on:
    postgres:
      condition: service_healthy
```

Grafana runs on port `3001` to avoid collision with AdGuard Home on `3000`.

### 7.2 Provisioning (Infrastructure as Code)

Grafana supports provisioning data sources and dashboards via YAML/JSON files mounted into the container. This means the Postgres connection and initial dashboards are version-controlled and applied automatically on container start — no manual UI setup required.

```
grafana/
└── provisioning/
    ├── datasources/
    │   └── postgres.yaml     ← Postgres connection config
    └── dashboards/
        ├── dashboard.yaml    ← tells Grafana where to find JSON files
        ├── overview.json     ← main overview dashboard
        ├── device.json       ← per-device drill-down dashboard
        └── geomap.json       ← world map — destination IPs plotted by country/city
```

### 7.3 Planned Dashboards

**Overview Dashboard**
- Total DNS queries in last 24h (stat panel)
- Queries per device over time (time series, one line per device)
- Top 20 queried domains across all devices (bar chart)
- Blocked queries count + rate (stat + time series)
- Open alerts table with risk score, device, type
- Top destination countries (bar chart — e.g. US 94%, DE 3%, RU 0.1%)

**Per-Device Dashboard** (drill-down via variable)
- Device selector variable: `SELECT name FROM "Device"`
- DNS query timeline for selected device
- Top domains for selected device with country + ISP columns
- Blocked queries for selected device
- Alert history for selected device
- Destination country breakdown for selected device (pie chart)

**World Map Dashboard** (Grafana Geomap panel)
- One dot per unique `(responseIp, country, city)` destination seen in the selected time range
- Dot size = query count to that location
- Dot color = red if any associated Alert exists, yellow if blocked, green otherwise
- Time range selector + device filter variable
- Table below map: country, city, ISP, query count, domains, first/last seen
- Intended use: immediately spot if a device is talking to unexpected geographies
- SQL backing the map:
```sql
SELECT
  g.lat, g.lon,
  g.country, g.city, g.isp,
  count(*) as query_count,
  max(e."queriedAt") as last_seen
FROM "DnsEvent" e
JOIN "IpGeoCache" g ON e."responseIp" = g.ip
WHERE e."queriedAt" >= $__timeFrom()
  AND e."queriedAt" <= $__timeTo()
  AND g.lat IS NOT NULL
GROUP BY g.lat, g.lon, g.country, g.city, g.isp
ORDER BY query_count DESC
```

## 9. Device Registration

Devices must be manually registered in the `Device` table. The collector ignores any source IP not present in this table (acts as an allowlist).

Registration is done via seed script or a future admin API. Each device must have a **static local IP** — either:
- Set a DHCP reservation in your router (bind MAC → IP), or
- Configure a static IP in the device's OS network settings

**Recommended static IP range for registered devices:** `192.168.1.10 – 192.168.1.50`

Example seed entries:
```ts
{ name: "macbook-benito",  ipAddress: "192.168.1.10", deviceType: "laptop",  owner: "benito" }
{ name: "iphone-benito",   ipAddress: "192.168.1.11", deviceType: "phone",   owner: "benito" }
{ name: "ipad-benito",     ipAddress: "192.168.1.12", deviceType: "tablet",  owner: "benito" }
```

## 11. Key Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Host machine offline → DNS fails | High — internet breaks for all registered devices | Per-device scope limits blast radius to your devices only; router DNS is untouched |
| Static IP drift (DHCP reassigns device IP) | Medium — events stored under wrong device or dropped | Set DHCP reservations in router for all monitored devices |
| AdGuard wizard not completed | Collector cannot authenticate | Documented in bootstrap; collector fails fast with clear error |
| High DnsEvent volume fills disk | Low initially, grows over time | Add a retention policy (cron job or Postgres partition) in Phase 2 |
| AdGuard API rate limiting | Low — 30s poll interval is conservative | Configurable via `COLLECTOR_POLL_INTERVAL_MS` |
| Duplicate events on collector restart | Data integrity | Dedup on `(deviceId, queriedAt, queriedHost)` unique constraint (to add in migration) |
| MaxMind .mmdb files missing on startup | Collector crashes at boot | Collector checks for file existence on startup and logs a clear error with download instructions |
| GeoLite2 data goes stale | Country/city data drifts from reality | `resolvedAt` TTL of 30 days; add a weekly cron to re-download `.mmdb` files via `geoipupdate` |
| Private IPs sent to MaxMind lookup | Lookup returns no data / error | Collector skips geo enrichment for RFC1918 ranges (`10.x`, `192.168.x`, `172.16-31.x`) |
