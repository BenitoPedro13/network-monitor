# Task 03 — Prisma Schema: IpGeoCache, SystemState, DnsEvent dedup constraint

**Phase:** 1 — Foundation  
**Group:** Database  
**Status:** Done  
**Date:** 2026-06-09

---

## What and Why

The existing schema has `Device`, `DnsEvent`, and `Alert`. The collector needs two more tables and one new constraint before it can be built:

1. **`IpGeoCache`** — stores geolocation data (country, city, lat/lon, ASN, ISP) for each unique destination IP. The collector looks up this table before hitting the MaxMind `.mmdb` file so the same IP is never resolved twice unnecessarily. Grafana joins this table to `DnsEvent` at query time to power the world map dashboard.

2. **`SystemState`** — a simple key/value table for persisting collector state across restarts. The only key we write today is `collector_cursor` — the RFC3339 timestamp of the last processed AdGuard event. Without this the collector would re-process the full backfill window every time it restarts.

3. **Unique constraint on `DnsEvent(deviceId, queriedAt, queriedHost)`** — prevents duplicate rows if the collector restarts mid-batch and re-fetches events it already wrote.

---

## What This Task Does

### Prisma schema changes (`apps/api/prisma/schema.prisma`)

Adds two new models and one `@@unique` directive:

**`IpGeoCache`**
- Primary key: `ip` (the destination IP string)
- Geo fields: `country`, `countryCode`, `city`, `lat`, `lon`, `asn`, `isp` — all nullable (MaxMind may not have data for every IP)
- `resolvedAt` — when the entry was last written; used for 30-day TTL refresh logic in the collector

**`SystemState`**
- Primary key: `key` (string — e.g. `"collector_cursor"`)
- `value` (string — stores the RFC3339 timestamp)
- `updatedAt` — auto-updated on every write

**`DnsEvent` change**
- Add `@@unique([deviceId, queriedAt, queriedHost])` — dedup guard

### Migration

Running `pnpm run db:migrate` generates and applies a new migration file under `apps/api/prisma/migrations/`.

## Decisions

- **`IpGeoCache.ip` as primary key (not cuid)** — the IP string is already unique and is the natural lookup key. Using it as PK avoids a separate unique index and makes the join in Grafana SQL simple: `JOIN "IpGeoCache" g ON e."responseIp" = g.ip`.
- **All geo fields nullable** — MaxMind GeoLite2 does not have data for every IP (private ranges, certain country allocations). The collector skips geo enrichment for RFC1918 IPs entirely; for public IPs with no data, nulls are acceptable — the world map simply won't render a dot for them.
- **`SystemState` as key/value not a typed table** — keeps the model simple. If more state keys are needed later they can be added without schema changes.
- **`@@unique` not a DB-level unique index separately** — Prisma generates the index from `@@unique`, so there's no need to write raw SQL.
